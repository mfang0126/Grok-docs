# 本轮对话详细回顾

> 范围：从投资人两题进入，到流程手册落地。
> 用途：看清「我们怎么聊的」「聊出了什么」「什么已经够用」「什么还缺」。
> 不替代成稿本身。成稿见 `final/`。

---

## 一、对话形式到底是什么

不是面试，也不是一次写好交出去。实际是三层套在一起：

1. **采访层**：你倒素材，我问、记、帮你找画面和转折。
2. **编辑层**：把敢材压成能交的答案，再改、再筛。
3. **元流程层**：事后把「怎么想、怎么聊」收成下一次可用的手册。

前半段三层混在一起，所以慢、容易撒、容易跑题。后半段才拆开。

---

## 二、怎么来回聊的（真实节奏）

### 节奏 A · 对不齐（最耗时）

你的开场是：两道投资人题 + 「为什么现在问这些」 + 「我们直接聊，你引导我」。

实际发生的错位：

- 你想要：伴着把题答完。
- 我开始做的是：用辩论 / 质疑 / 追问证据来挑逻辑。
- 你的反馈很明确：问的跟原题无关、太 aggressive、在争、在跑题、不要受害者叙事。

这一节的价值不是答案，是把规则碰出来：

- 先定题，不先辩「投资人为什么问」。
- 不用履历标准审人。
- 不把人生经历写成悲情脑。
- 对方说回题，必须立刻回题。

### 节奏 B · 改规则：先倒素材，不写

你明确说：我继续给信息，不见得都用；把童年 / 少年 / 青年素材堆齐，再决定怎么写。

这一节才是正确采访。协助侧只做三事：

- 听完一段，标出「最有画面」和「不要进答案」。
- 分清「当时觉得不对劲」和「现在回看才明白」。
- 不把社会圈子细节、自身外貌、花钱进好学校这类写进正文。

### 节奏 C · 压稿 + 改稿

顺序是：

1. 先出第一题单版草稿
2. 你评「写得不错」，要求把素材 + 答案存档
3. 误存进公开仓库 → 改建私有仓库 `Grok-docs` → 从公开仓库删文件
4. 再做第二题：同样是倒素材 → 压一段 → 补一句主动性 → 存档

### 节奏 D · 定稿 + 分版

后续在仓库里出现了更完整的一层（`final/`）：

- 三个倾向：克制 / 锋芒 / 真诚
- 选版说明 + claim 边界
- 第一题、第二题各三版
- 相对早期草稿的取舍清单

### 节奏 E · 把过程本身流程化

你先问「整个采访能不能流程化」，再说明确：

- 要的是怎么想、怎么聊、怎么收
- 给下一次的自己，也给另一个人
- 细节不要太多

产出：`process/people-questions.md`

## 三、关键内容（不重写故事，只写被用到的结论）

### 第一题的弧线

**只信自己验证过的东西 → 这让你能抑、能做、技术强 → 代价是不求助、错过机会 → 带人之后改成「我判断，别人放大」。**

被留下的锚：

- 童年：结婚不到一百天离婚，多家轮住；两边价值观相反；父母辈在身边去世
- 少年：最差的班 + 「留余地」；小学起修电脑这条技术线
- 青年：绿皮车 / 大年三十 / 雅思 5.5；出国借钱打工；第二份工作 manager 点破；带团队后改结构

被刻意不写进正文的：

- 「不安全感」这个心理学标签
- 「我胖、不淘气」
- 班里混社会的细节
- 「花钱进好高中」
- 把「小时候就看明白了」当成事实

### 第二题的弧线

**能力不是「技术好」，是「方向还没定型时能拆架构，并且会自己动手验证」。别人来找你：方向不清，或代码卡死。**

被留下的锚：

- 从小学起就有人为装机 / 选型号来问
- 多 agent / harness 这个词还没普及时就在做
- 用真项目验证：eSIM、车牌、智能家居、root / jailbreak
- ForgeLingo 三个架构判断（不赌模型、数据价值在对齐不在录音、不追官方分数等价）

被刻意不写进正文的：

- 传记和心理学书清单（消费型证据）
- 「我一看 Grok 就明白」这类自我评价
- 把「我预测准」当成主结论

### 两题共用的一句话

第一题讲这条弧怎么长出来。
第二题讲这条弧现在怎么变成别人找你的理由。

## 四、结构怎么长出来的

最终库结构：

```
Grok-docs/                    私有
  investor-q1/
    01-raw-details.md         采访原料
    02-drafted-answer.md      早期单版草稿
  investor-q2/
    01-raw-details.md
    02-drafted-answer.md
  final/
    00-how-to-choose.md       怎么选倾向 + claim 边界
    q1-three-versions.md
    q2-three-versions.md
  process/
    people-questions.md       可复用方法
    session-retrospective.md  本文
```

结构上的演化：

1. 最早：聊天记忆里一切都在
2. 中期：每题两个文件（原料 + 草稿）
3. 后期：原料不动，成稿进 `final/`，分三个读者口呰
4. 最后：把方法从内容里抽出来，放进 `process/`

这个分层就是下一次应该一开始就用的，不要再从聊天记忆里摸。

## 五、怎么被用的

| 产出 | 用法 |
|---|---|
| `01-raw-details` | 备查、补料、防止成稿丢掉画面 | 
| `02-drafted-answer` | 过渡稿，不建议直接交 | 
| `final/` 三版 | 真正可交。先按读者选一个倾向，两题同选 | 
| `00-how-to-choose` | 交之前决定语气和 claim 边界 | 
| `process/people-questions` | 下一道类似题的开场脚本 | 
| 本回顾 | 看清这轮哪些对话动作有效、哪些浪费时间 |

实际交件时：

- 只交 `final/` 里选中的那一版
- 不交 raw
- 不把三版一起交给同一个投资人

## 七、下一次直接怎么开

1. 打开 `process/people-questions.md`
2. 复制开场四句
3. 新建 `qX/01-raw-details.md`，先只采集
4. 筛完再写 `02-drafted-answer.md`
5. 要换读者时才进 `final/`

不要再从「投资人为什么问这题」辩起。
